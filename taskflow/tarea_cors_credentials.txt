DIFERENCIA ENTRE CORS_ALLOWED_ORIGINS Y CORS_ALLOW_CREDENTIALS

1. CORS_ALLOWED_ORIGINS:
   Define la lista blanca (allowlist) de dominios, esquemas y puertos (orígenes)
   que tienen permitido realizar peticiones HTTP hacia la API desde el navegador.

2. CORS_ALLOW_CREDENTIALS:
   Es una bandera booleana (True/False) que indica si el navegador debe incluir 
   credenciales (cookies, encabezados de autorización como 'Authorization: Bearer', 
   o certificados TLS) en las peticiones entre dominios cruzados (Cross-Origin).

¿EN QUÉ ESCENARIO SE NECESITA CORS_ALLOW_CREDENTIALS?
Se requiere habilitar en True cuando la API y el Frontend están alojados en dominios u 
orígenes distintos (por ejemplo, frontend en http://localhost:3000 y backend en http://localhost:8000) 
y el cliente necesita enviar cookies de sesión (HTTP-only cookies) o encabezados de 
autorización HTTP explícitos (Bearer JWT) para autenticarse en peticiones Cross-Origin.
